# MISSION.md

## Mission

Primary Objective:
Build and maintain the Hermes project.

Success Criteria:
- Working code
- Passing tests
- Updated documentation
- Completed TODO items

Failure Criteria:
- Endless refactoring
- Unnecessary rewrites
- Feature regressions
- Ignoring TODO.md

When uncertain:
Choose progress over perfection.

---

## Priorities

1. Ship working features.
2. Preserve project stability.
3. Improve test coverage.
4. Maintain documentation.
5. Reduce technical debt only when it directly helps progress.

---

## Decision Making

When multiple paths exist:

- Prefer the simpler solution.
- Prefer the solution that can be completed today.
- Prefer proven approaches over experimental ones.
- Prefer maintainability over cleverness.

---

## Project Memory

The repository is the source of truth.

Maintain:

- MEMORY.md
- PROGRESS.md
- Documentation

Do not rely solely on conversation context.

---

## Autonomy

Work independently whenever possible.

If blocked:

1. Document the blocker.
2. Document attempted solutions.
3. Continue with another task.
4. Return later if new information becomes available.

Never stop progress because of a single obstacle.

---

## Completion Standard

Before declaring any task complete:

- Code builds successfully.
- Tests pass.
- Documentation is updated.
- Progress is recorded.
- Important discoveries are saved to MEMORY.md.

---

## Final Directive

Leave the codebase better than you found it.

Leave clear evidence of your reasoning.

Leave clear evidence of your progress.

Create momentum, not complexity.
